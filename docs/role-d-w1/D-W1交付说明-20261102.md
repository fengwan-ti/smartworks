## 三、怎么用

### 3.1 复现路网（改坐标 / 换车间）

```bash
python scripts/gen_road_network.py
```

脚本读写都相对仓库根目录：坐标表在脚本里的 `NODES` / `EDGES` 两张常量表，输出写到 `data/`。
本次实测：跑完三个文件与仓库里已提交版本**逐字节一致**（`git status` 无变更），即**数据可复现**。

### 3.2 校验数据是否自洽

```bash
python -c "import json;d=json.load(open('data/equipments-v1.json',encoding='utf-8'));print(len(d['equipments']))"
```

设备台账里每台设备的 `workstation_node` 都是路网中的 `dock` 节点（已逐台核对，8/8 命中）。
这条对应的是「新增设备 → 立刻参与排产」验收项（D4）：台账 → 能力 → 绑装卸点 → 排产候选集里出现，全程不改代码。

## 四、四条必须记住的口径

**1. 坐标是设计值，不是实测值。**
设备清单（说明书 §2.2 的 8 台）和工序顺序（B 的 6 条工艺路线）是真的；**每个节点的坐标是按工艺流程排出来的，不是测绘的**，也没有 CAD 图纸。
答辩口径：*「按 8 台设备的工艺顺序和中小型机加工车间典型布局设计，节点坐标参数化配置，接真实车间只需替换坐标数据，调度算法不用改。」*
不说「这是我们车间的实际布局」，也不要编通道宽度的依据。

**2. 距离矩阵不可达填 `null`。**
不填 `-1`、不填 `999999`。填了「很大但有限」的数，AGV 调度会把不可达的活当成「绕远但能干」，算出来的方案现场跑不了。

**3. 矩阵不对称是正常的。**
主通道北段设了一条单行道（`N007 → N008`），所以 `d(A,B) ≠ d(B,A)` 是有意为之。任何「矩阵对称」的断言都会失败，别当 bug 改。

**4. 任务表写 25 节点 / 35 边，实际交 29 节点 / 48 边。**
多出的 4 个是加工区内部横向通道。不加这几条支路，跨设备最短路径要绕回主通道，**平均绕路比从 1.30 升到 1.5 以上**。数量不是硬约束，说明书 §2.2 原文写的是「设计基线，可通过数据配置调整」。
