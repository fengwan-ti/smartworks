## 一、路网编号规则与几何坐标系　→ 插在 `docs/api-contract.md` 一、通用约定之后

### 1.1 坐标系

| 项 | 约定 |
|---|---|
| 单位 | 毫米（mm），整数 |
| 原点 | 车间西南角（原料仓左下） |
| 方向 | x 轴向东（右为正），y 轴向北（上为正） |
| 范围 | 第一代 x ∈ [0, 60000]，y ∈ [0, 30000] |
| 前端 | 直接使用该坐标，ECharts 只做缩放，不做旋转与换算 |

### 1.2 节点编号

| 项 | 约定 |
|---|---|
| 格式 | `N` + 3 位数字，如 `N001` |
| 编法 | 按 y 再 x 的扫描顺序编（第一行从左到右，第二行从左到右…），**不带业务含义** |
| 类型 | 放在 `type` 字段，不放进编号。取值：`lane`（通道）/ `dock`（装卸点）/ `charger`（充电位） |
| 唯一 | `code` 全表唯一，导入时重复直接报错 |

> 为什么不用 `DK-01` 这种业务编号：装卸点会增减，带含义的编号一旦改类型就得重编，边全部要跟着改。

### 1.3 边与距离

| 项 | 约定 |
|---|---|
| `distance` | **沿路长度**（不是两节点直线欧氏距离），单位 mm |
| 连边条件 | 只有两节点之间可以直线通行才连边；被设备/墙阻断的不连 |
| `is_bidirectional` | 默认 true；主通道若设单行道则单条边置 false，反向另建一条 |
| 重复边 | `(from_node, to_node)` 唯一；反向边由 `is_bidirectional` 表达，不建两条 |

### 1.4 距离矩阵口径（A 的任务 3 与 D 的任务 1/2 共用）

| 项 | 约定 |
|---|---|
| 形状 | N×N，N 为节点总数，行列顺序 = 按 `code` 升序 |
| 对角线 | 0 |
| 不可达 | **`null`**（不用 -1、不用 999999） |
| 类型 | 整数（mm） |
| 算法 | Dijkstra，复杂度与节点数量无关的约定：25 节点全对全 ≤ 50 ms |
| 出参结构 | `{"node_ids": ["N001", ...], "matrix": [[0, 1200, null, ...], ...]}` |

> **`null` 这一条必须统一**：填 999999 会让 AGV 调度把我不可达的任务当成"绕远但能做"，算出方案现场跑不了。

### 1.5 路网导入 JSON 格式

```json
{
  "version": "1.0",
  "unit": "mm",
  "nodes": [
    {"code": "N001", "x": 1000, "y": 2000, "type": "lane", "name": "主通道-1"}
  ],
  "edges": [
    {"from": "N001", "to": "N002", "distance": 1500, "is_bidirectional": true}
  ]
}
```

## 二、`step_type` 取值字典（草案）　→ 这是全项目缺口，请 A 与 B 一起定

**为什么必须由 B 定**：工序模板（B）、工序路线（B）、设备能力（D）、员工技能（A）四处都在用，B 是工艺主责。
**我这份只是草案**，B 改我就改。

| step_type | 中文 | 所需设备类型 | 标准工时(h) 参考 | 备注 |
|---|---|---|---|---|
| `cutting` | 下料 | 锯床 / 剪板 | 0.20 | 6 种零件全部第一步 |
| `rough_turning` | 粗车 | 数控车床 | 0.50 | 盘类、轴类 |
| `finish_turning` | 精车 | 数控车床 | 0.60 | 与粗车同设备类型，不同工序 |
| `milling` | 铣削 / 铣面 | 加工中心 | 0.45 | |
| `slot_milling` | 铣槽 | 加工中心 | 0.35 | 端盖 B 用 |
| `gear_milling` | 铣齿 | 滚齿机 / 加工中心 | 1.20 | 齿轮轴 C 用 |
| `drilling` | 钻孔 | 钻床 / 加工中心 | 0.30 | 法兰盘 A、连接板 E |
| `grinding` | 磨外圆 | 磨床 | 0.70 | 齿轮轴 C 用 |
| `deburring` | 去毛刺 | 去毛刺台 | 0.15 | 通用 |
| `cleaning` | 清洗 | 清洗机 | 0.10 | 通用，可插任意族 |
| `inspection` | 检验 | 三坐标 / 影像仪 | 0.25 | 全部最后一工序 |

**约定**：
1. 全小写，下划线分隔，**不复数、不缩写**（`turning` 而不是 `turn`）。
2. 一个 `step_type` 可以要求**多种**设备类型（上表「所需设备类型」是主要那个，实际存在 `params` 里）。所以设备能力的匹配口径是：**设备的 `step_type` 列表包含工序要求的 `step_type` 即可**，不要求 1:1。
3. 新增一个 `step_type` 不写代码，只加数据字典 + 一条工序模板。

## 三、设备台账与能力参数（D 的 W1-D2 交付）　→ 插在契约 2.9 节之后

### 3.1 `eq_equipment` 设备台账

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | bigint 自增 | ✔ | 主键 |
| code | varchar(32) 唯一 | ✔ | 设备编码，规则 `EQ-<类型缩写>-<2位序号>`，如 `EQ-CNC-01` |
| name | varchar(64) | ✔ | 设备名称 |
| model | varchar(64) | | 型号 |
| manufacturer | varchar(64) | | 厂商 |
| workshop_id | 外键→masterdata.workshop | ✔ | 所属车间 |
| workstation_id | 外键→masterdata.workstation | | 所属工位（即 AGV 装卸点，用于生成转序任务） |
| status | varchar(16) | ✔ | `normal` / `wearing` / `abnormal`（与状态机枚举一致） |
| install_date | date | | 安装日期 |
| is_active | bool | ✔ | 是否启用，默认 true |
| remark | text | | 备注 |

> `status` 与 `eq_equipment_status_log.status` 取值一致，但语义不同：台账的 `status` 是**当前值**（由最近一条状态记录同步），状态记录是**历史**。**不要让前端直接写台账 status**，只读。

### 3.2 `eq_equipment_capability` 设备能力（D 写，B 只读）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | bigint 自增 | ✔ | 主键 |
| equipment_id | 外键→eq_equipment | ✔ | 设备 |
| step_type | varchar(32) | ✔ | 可执行的工序类型，取值见第二节 |
| precision_level | varchar(16) | | 精度等级：`high` / `medium` / `normal` |
| capacity_per_hour | decimal(12,3) | | 每小时可加工件数（产能） |
| setup_minutes | int | | 换型准备时间（分钟），排产用 |
| params | JSONField | | 动态参数，见下 |
| is_active | bool | ✔ | 是否启用 |

唯一约束：`(equipment_id, step_type)`。

`params` 第一版约定结构（**B 排产只需要读 `step_type / capacity_per_hour / precision_level`**，params 是给详情页和后续扩展用的）：

```json
{
  "max_spindle_speed": 6000,
  "max_turning_diameter": 320,
  "max_workpiece_length": 800,
  "tolerance_mm": 0.02,
  "axis_count": 3,
  "coolant": true
}
```

**为什么这么切**：B 的排产匹配如果要去读 JSON 里的字段，就等于「排产依赖动态参数结构」，以后加设备就要改代码——这正好违反说明书第 11 章 N4「元数据驱动、零改代码」的创新点。所以**匹配只走三列**，JSON 只做展示。

### 3.3 新增设备 → 立刻参与排产的路径（验收 D4）

1. 设备台账建一条，`is_active=true`
2. 能力表建 ≥1 条，`step_type` 用第二节字典里的值
3. 绑定 `workstation_id`（这样搬运任务找得到它）
4. B 的排产跑一次 → 该设备出现在候选集中、出现在产能负荷里
5. **全程不改代码、不改配置**

这条我在 W2 做完后要实际走一遍，作为 D4 的自测记录。
