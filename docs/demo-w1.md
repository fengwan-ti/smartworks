# 第一周演示脚本（周五 10 分钟）

> 目的：让三个人都亲眼看到系统跑起来，并确认自己机器上也能跑。
> 这不是给老师看的演示，是团队内部的第一次联合验收。

## 一、演示前 5 分钟准备

| 检查 | 做法 |
|---|---|
| 三人是否都跑通了 | 各自双击 `0-环境自检.bat`，截图发群 |
| 投影/共享屏幕 | 组长开屏幕共享 |
| 浏览器 | 提前打开 `http://localhost:5173` 并登录好，避免现场等 |

## 二、演示流程（10 分钟）

| 时段 | 内容 | 谁 |
|---|---|---|
| 0~1 分 | 一句话说明：这是什么东西、第一周做到哪一步 | 组长 |
| 1~3 分 | 登录 → 侧边栏菜单 → 点"用户管理"看到占位页（说明菜单由后端驱动） | 组长 |
| 3~6 分 | 工作台三个按钮：成功 / 分页 / 异常，逐个点并说明各自证明什么 | 组长 |
| 6~8 分 | 打开 Swagger 页面 `http://localhost:8000/api/docs/`，说明后端接口都在这 | 组长 |
| 8~10 分 | 说明分工与下周各自要做什么，确认每人 W2 第一件事 | 组长 |

## 三、三个按钮分别证明什么（要讲出来，不能只点）

| 按钮 | 证明的事 |
|---|---|
| 验证成功响应 | 后端所有接口返回统一结构 `{code, message, data}`，前端 `request.js` 自动拆包 |
| 验证分页响应 | 分页字段被统一成 `count / page / page_size / results`，前端表格组件可以直接用 |
| 验证异常响应 | 业务错误被统一拦截成中文提示，前端不用每个页面自己写错误处理 |

**这三件事的意义**：四个人后面各写各的模块，只要都走这套格式，合并时不用反复对齐。

## 四、讲解关（每人 5 分钟，组长提问）

按《代码导读》第 10 章的五道题抽三题问。必问的两道：

1. **页面点一个按钮，请求经过哪几个文件才到数据库？**（考察是否理解八步链路）
2. **侧边栏菜单是写死的还是后端给的？加一个岗位要改代码吗？**（考察是否理解元数据驱动）

答不出的，回去补《SmartWorks 代码导读》第 1 轮和第 3 轮。

## 五、演示结束后立刻做

| 事 | 负责人 |
|---|---|
| 确认三人 `0-环境自检.bat` 三项全绿 | 组长 |
| 把本周问题记进 `docs/api-status.md` 或群待办 | 组长 |
| 宣布 W2 各自第一件事（见下） | 组长 |
