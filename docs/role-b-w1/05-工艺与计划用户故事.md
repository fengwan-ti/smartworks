## 1. M03 工艺配置中心（多品种与新产品的枢纽）

### US-B-01 工序模板库维护（P0 / W2 D1）

- **用户故事**：作为一个工艺员，我想要把常用工序（粗车、精车、钻孔…）维护成带标准工时、所需设备类型、关键参数与检验要求的模板，以便于不同零件的同类工序标准一致、新零件不用重复填写。
- **验收标准**：
  1. 新增/编辑必填 `code`、`name`、`step_type`、`std_hours`、`required_equipment_type`；`std_hours ≤ 0` 返回 400 + 12002，`> 24` 返回 12003；
  2. `step_type` 或设备类型不在枚举内返回 12004；`code` 重复返回 12001；
  3. 列表支持 `?step_type=` 筛选与 `search`（code/name）；分页返回统一响应体；
  4. 停用（`is_active=false`）后不再出现在"新增路线可选模板"里；已被路线引用的模板删除返回 12008。
- **接口 / 页面**：`/process/templates/`（#32/#33）；`views/process/TemplateList.vue`。

### US-B-02 从模板库拼装工艺路线（P0 / W2 D2）

- **用户故事**：作为一个工艺员，我想要在一条路线上从模板库添加工序、调整顺序、删除工序，并为每道工序填写本零件的工时与参数，以便于不写代码就能配出新零件的加工路线。
- **验收标准**：
  1. 工序按 `seq` 升序返回；新增默认 `seq = 当前最大值 + 10`；调序后 `(route, seq)` 不得重复（12005）；
  2. 每道工序可覆盖模板的 `std_hours`、`required_equipment_type`、`key_params`；未填时回落到模板值；
  3. 工序数 ≥ 1 才能把路线置为 `active`（否则 12006）；同一产品已有 active 路线时再置 active 返回 12007；
  4. 生成路线后，`GET /process/routes/{id}/steps/` 能按 §6 的 6 条路线完整复现（含连接板 E 的下料覆盖设备类型）。
- **接口 / 页面**：`/process/routes/`、`/routes/{id}/steps/`（#36/#37/#39）；`views/process/RouteDesign.vue`（表格行增删排序，暂不做拖拽）。

### US-B-03 新零件复制同族路线（P1 / W2 D4）

- **用户故事**：作为一个工艺员，我想要新建零件时直接复制同族产品的工艺路线，以便于不用从零填十几道工序。
- **验收标准**：
  1. `POST /process/routes/{id}/copy/` 入参 `new_product_id`，生成新产品的 `draft` 路线（version=1），工序、工时、参数、设备类型完整复制；
  2. 源路线不受影响；目标产品已有 active 路线返回 12022；
  3. 复制后 `family_id` 自动取新产品的族，且与 `product.family_id` 一致（不一致 12004）；
  4. 支持按族查参考路线：`GET /process/routes/?family_id=&status=active`。
- **接口 / 页面**：`/process/routes/{id}/copy/`（#38）；路线设计页"从同族复制"按钮。

### US-B-04 工序绑定设备类型要求（P1 / W2 D2）

- **用户故事**：作为一个工艺员，我想要为每道工序指定所需的设备类型，以便于排产时自动匹配到合适的机床。
- **验收标准**：
  1. `required_equipment_type` 取值来自 7 个设备类型（见 06 数据字典 §3.2）；
  2. 路线详情返回该字段，排产服务按 `step_type + required_equipment_type` 反查 D 的设备能力（I-11）；
  3. 某工序无任何可用设备时，路线生效前给出警告（不阻断）；W3 排产无候选设备时报 12020 并指出工序。
- **接口 / 页面**：`/process/routes/{id}/steps/`；`/process/equipment-capabilities/`（#42，只读）。

### US-B-05 BOM 维护（P0 / W2 D3）

- **用户故事**：作为一个工艺员，我想要维护产品的单层物料清单（物料、单件用量、损耗率），以便于齐套检查与领料单能自动算量。
- **验收标准**：
  1. 主表 + 明细子表一起保存（事务）；明细 `qty_per ≤ 0` 返回 12009，`loss_rate` 不在 0~100 返回 12010；
  2. 同产品同版本唯一；同一产品最多一条 active BOM，否则 12011；
  3. 明细物料必须来自 masterdata（A 维护），不允许在 BOM 里新建物料；
  4. 只做单层 BOM，不提供嵌套/装配（第一代非目标）。
- **接口 / 页面**：`/process/boms/`、`/boms/{id}/items/`（#34/#35）；`views/process/BomEdit.vue`。

### US-B-06 换型矩阵维护与 Excel 导入（P2 / W2 D5）

- **用户故事**：作为一个计划员，我想要维护"从产品 A 换到产品 B 要多少分钟"并支持 Excel 批量导入，以便于多品种排产有真实的换型约束。
- **验收标准**：
  1. 新增/编辑：分钟必须在 0~480（12012）；前后产品不能相同（12013）；产品对不能重复（12014）；
  2. 导入文件缺列或产品编码不存在返回 12023，整批回滚并返回失败行号与原因；
  3. 列表支持按 `from_product_id` / `to_product_id` / `source` 筛选；`source` 必填且为枚举；
  4. 缺失产品对不报错：排产按默认规则兜底并返回 `default_used=true`（口径见 03 文档 §6）。
- **接口 / 页面**：`/process/changeovers/`、`/changeovers/import/`、`/changeovers/matrix/`（#40/#41 + 新增 40a）；`views/process/ChangeoverMatrix.vue`。

### US-B-07 试制数据回流（基础版）（P2 / W2~W3）

- **用户故事**：作为一个工艺员，我想要在试制工单报工后看到实测工时与标准工时的偏差，以便于用真实数据修正标准工时。
- **验收标准**：
  1. 试制工单报工完成后，接口按 `product_id` 汇总"实测工时 / 标准工时 / 偏差率"；
  2. 页面表格展示，偏差 > 20% 标红；**不自动改标准工时**，由工艺员人工确认后手改；
  3. 无报工数据时显示"—"而不是报错。
- **接口 / 页面**：读 C 的 `pd_report_record`（汇总接口 `GET /production/reports/summary/?work_order_id=`）；`views/process/TrialFeedback.vue`。

## 2. M04 订单与需求预测

### US-B-08 销售订单台账（P0 / W3 D1）

- **用户故事**：作为一个计划员，我想要在一个页面看到所有销售订单的交期与状态，以便于快速判断哪些单要优先安排。
- **验收标准**：
  1. 列表支持 `status`、`customer`、`order_date` 区间、`due_date` 区间筛选 + `search`（订单号）；
  2. 新增订单含明细行（`product_id`、`qty`、`due_date`）；`qty ≤ 0` 返回 12015，`due_date < order_date` 返回 12016；
  3. 默认按 `due_date` 升序；逾期未完成订单高亮；
  4. 主表 + 明细在同一事务保存，任一明细失败整体回滚。
- **接口 / 页面**：`/order/sales-orders/`、`/sales-orders/{id}/items/`（#43/#44/#45）；`views/order/SalesOrderList.vue`。

### US-B-09 订单状态机（P1 / W3 D1）

- **用户故事**：作为一个计划员，我想要按"草稿→已确认→已排产→生产中→已发货→关闭"推进订单状态，以便于订单进度和车间执行保持一致。
- **验收标准**：
  1. 仅 `draft` 可 `confirm`；已排产（`scheduled` 及之后）不允许改数量/产品，返回 12017；
  2. 取消（`cancelled`）必须填原因；`closed` / `cancelled` 为终态，不可回转；
  3. 每次状态变更写 `core_operation_log`（A 的日志），记录前后状态与操作人；
  4. 状态值严格用《工作包》2.6 枚举，前端中文名走字典（I-02）。
- **接口 / 页面**：`/order/sales-orders/{id}/confirm/`、`/cancel/`（#46/#47）；订单详情页状态条。

### US-B-10 需求预测运行（任务 7）（P1 / W5 D1）

- **用户故事**：作为一个计划员，我想要选择产品与预测周数，让系统根据历史订单给出未来需求预测值与置信区间，以便于提前备料与预留产能。
- **验收标准**：
  1. `POST /order/forecasts/run/` 入参 `product_ids`、`periods`（4~8）、`model`（sarima / moving_average / exp_smoothing）；历史周期 < 24 返回 19401，模型不支持返回 19402；
  2. 出参每条含 `product_id`、`period`、`forecast_qty`、`lower_bound`、`upper_bound`、`model`、`mape`、`rmse`，整体含 `cost_ms`；
  3. 结果落 `or_demand_forecast`；同一 product+period 重跑覆盖旧值但保留历史记录（供准确率复盘）；
  4. 页面：实际曲线（实线）+ 预测（虚线）+ 置信区间（阴影）+ 指标卡；
  5. 训练/测试**按时间顺序划分**，服务内固定，不暴露随机划分参数。
- **接口 / 页面**：`/order/forecasts/run/`、`/forecasts/`（#48/#49）；`views/order/ForecastRun.vue`。

### US-B-11 预测一键转 MPS（P1 / W5 D4）

- **用户故事**：作为一个计划员，我想要把预测结果一键转成主生产计划，以便于不用手工抄一遍数据。
- **验收标准**：
  1. `POST /order/mps/from-forecast/` 生成 MPS 主表（`period`、`status=draft`）+ 明细（`product_id`、`qty`、`source=forecast`）；
  2. 明细留痕 `source` 与来源 forecast；重复生成需二次确认后覆盖；
  3. 明细为空返回 12018。
- **接口 / 页面**：`/order/mps/from-forecast/`（#51）；`views/order/MpsList.vue`。

### US-B-12 齐套检查与缺口清单（P1 / W3 D3）

- **用户故事**：作为一个计划员，我想要在下单或排产前知道原料是否齐套，以便于避免排了产却领不到料。
- **验收标准**：
  1. `POST /order/mps/{id}/check-kit/`，按 active BOM 展开到物料级；
  2. 返回 `ready`（bool）+ 缺口清单 `[{material_id, material_code, required, available, shortage}]`；无 active BOM 返回 12019；
  3. `available` 取 C 的库存可用量（I-09）；C 未上线时按契约字段用 mock，开关切换；
  4. 缺口按 `shortage` 降序；页面表格标红。
- **接口 / 页面**：`POST /order/mps/{id}/check-kit/`（#52）；`views/order/KitCheck.vue`。

## 3. M05 排产与人员统筹

### US-B-13 规则版排产（P0 / W3 D3）

- **用户故事**：作为一个计划员，我想要系统按交期、换型时间和设备利用率排出工单顺序与工序时间，以便于不再靠经验拍脑袋。
- **验收标准**：
  1. `POST /planning/schedule-plans/run/` 入参 `plan_name`、`mps_id` 或 `order_ids`、`frozen_until`、候选设备；出参 `plan_id` + `kpi`（交期达成率、换型次数、设备利用率、计算耗时）；
  2. 生成 `pl_work_order`（按产品）与 `pl_work_order_operation`（工序级 `equipment_id`、`plan_start`、`plan_end`、`seq`）；
  3. 同一设备同一时段不得重叠；冻结区工单计划时间不变；换型时间从 `pr_changeover_matrix` 取，缺失走默认规则并标记 `default_used`；
  4. 无工单可排返回 12020；`frozen_until` 非法返回 12021；
  5. 200 工单 / 600 工序规模求解 ≤ 5s（本机 SQLite）。
- **接口 / 页面**：`/planning/schedule-plans/run/`（#59）；`views/planning/ScheduleWorkbench.vue`。

### US-B-14 工单/工序甘特图（P1 / W3 D4）

- **用户故事**：作为一个计划员，我想要看到工单与工序级的甘特图，以便于直观看出设备占用与交期风险。
- **验收标准**：
  1. 横轴时间、纵轴设备（可切换为工单）；工序块颜色按 status；
  2. 与排产结果一致（同一 `plan_id`），可下钻到工单详情；
  3. 画出交期线；超期工单标红。
- **接口 / 页面**：`/planning/schedule-plans/{id}/`、`/work-orders/{id}/operations/`（#55）；`views/planning/Gantt.vue`。

### US-B-15 方案对比（P2 / W6 D2~D3）

- **用户故事**：作为一个计划员，我想要对比新旧两个排产方案的交期达成率、换型次数与利用率，以便于向上级解释为什么调整。
- **验收标准**：
  1. `GET /planning/schedule-plans/compare/?ids=1,2` 返回两组 kpi 与差异；
  2. 页面显示对比表 + 关键差异说明（如"换型次数减少 3 次，交期达成率 +2.1%"）；
  3. kpi 取自 `pl_schedule_plan.kpi` 快照，不重算历史方案。
- **接口 / 页面**：`/planning/schedule-plans/compare/`（#61）；`views/planning/PlanCompare.vue`。

### US-B-16 冻结区与急单重排（P2 / W6 D4）

- **用户故事**：作为一个计划员，我想要在急单插入时一键重排且不动已开工/已派工的工单，以便于不打乱现场。
- **验收标准**：
  1. `frozen_flag=true` 或已开工工单的计划开始/结束时间完全不变；
  2. 输出变动工单列表与变动量（顺序变动数、时间偏移分钟）；
  3. 目标函数对"顺序变动量"加惩罚（最小扰动），权重可配；
  4. 重排前后自动保存为两个 plan，可对比（US-B-15）。
- **接口 / 页面**：`/planning/schedule-plans/run/`（#59，带 `frozen_until`）；工作台"重排"按钮 + 差异弹窗。

### US-B-17 产能负荷（设备 + 人员）（P2 / W7 D1）

- **用户故事**：作为一个计划员，我想要按设备与人员两个维度看未来产能负荷，以便于知道瓶颈到底在人还是在机。
- **验收标准**：
  1. 按日/周聚合 `planned_hours`（工序计划）与 `capacity_hours`（设备班次 / A 的人员排班）；
  2. 设备维度负荷率 > 100% 标红；人员维度同；
  3. 输出瓶颈提示：负荷率 Top3 的设备/人员 + 所在工序。
- **接口 / 页面**：`/planning/capacity-loads/`（#62）；`views/planning/CapacityLoad.vue`。

### US-B-18 派工到工位与人员（P1 / W3 D5）

- **用户故事**：作为一个班组长，我想要把工单工序派给具体的机床与人员，以便于责任清晰、报工能对得上人。
- **验收标准**：
  1. `POST /planning/dispatches/` 写回 `operation.equipment_id` / `operator_id` 并记录 `dispatched_at`；
  2. 人员技能不匹配（A 的技能矩阵 I-04 中无该 `step_type`）时给出警告，但允许强制派工（需 `remark`）；
  3. 派工后工序状态仍为 `pending`，开工由 C 的接口推进；
  4. 同一工序重复派工以最后一次为准并留痕。
- **接口 / 页面**：`/planning/dispatches/`（#58）；`views/planning/Dispatch.vue`。
