## 2. 工序 start/complete 的 service 函数

B 已经实现，C 的 `production/services.py → _advance()` 不用改，把 13050 降级分支去掉即可：

```python
# 导入：from apps.planning import services
services.operation_start(work_order_id: int, seq: int, user=None)
services.operation_complete(work_order_id: int, seq: int, user=None)
```

行为：

- `operation_start`：工序 `pending/dispatched → in_production`；工单 `planned/released → in_production`；已完工重复开工报 `12017`；
- `operation_complete`：工序 → `completed`；全部工序完工 → 工单 `completed`，并 best-effort 通知 D 撤销未开始搬运任务；
- 返回 dict：`{work_order_id, seq, operation_status, work_order_status}`。

## 4. 工单/工序状态枚举（书面定稿）

```python
# WorkOrderStatus（pl_work_order.status）
draft            # 草稿
planned          # 已排产
released         # 已下达
in_production    # 生产中
completed        # 已完工
closed           # 已关闭
cancelled        # 已取消

# OperationStatus（pl_work_order_operation.status）
pending          # 待开始
dispatched       # 已派工
in_production    # 加工中
completed        # 已完成

# SchedulePlan.status
draft            # 草稿
confirmed        # 已确认
```

非法流转统一报 **12017**；工单已完工后工序不能再开工/完工（也是 12017）。
