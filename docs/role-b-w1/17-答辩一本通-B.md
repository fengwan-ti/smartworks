## 2. 业务主链（讲故事版）

```
销售订单（6 张，4 张已确认）
  ↓ 确认订单
MPS 主生产计划（从已确认订单聚合：PF-PL-001/002、PF-SH-001/002 共 60/50/40/35 件）
  ↓ 按生效 BOM 展开
齐套检查（需求 = MPS 数量 × 单件用量 × (1+损耗率)，扣 C 的库存可用量）
  ↓ 生成工单
规则版排产（交期 + 优先级排序；每道工序选最早可用设备；换型矩阵加换型时间）
  ↓ 工序级计划（甘特数据）
派工（按 A 的员工技能找合格操作工）
  ↓
转序搬运 leg → D 的 from-legs 批量派生 AGV 搬运任务
  ↓
C 报工开工/完工 → 回写工序、工单状态
  ↓
生产看板（方案 KPI、工单进度、报工良品、延迟、瓶颈、齐套）
```

一句话：**订单说“做什么、什么时候要”，工艺路线说“怎么做”，BOM 说“用什么料”，排产说“哪台设备、什么时候、做哪道工序”，派工说“谁来做”，D 管“料怎么搬”，C 管“做了多少、合不合格”。**

## 5. 算法一：需求预测（任务 7）

### 5.1 数据

- 教师零售数据集（913,000 行、10 店 × 50 商品 × 1826 天）；
- 10 店按商品合并 → 按 5 年总销量取 6 个代表商品（item 15/25/8/31/42/5）→ 映射 6 种零件；
- **K=100 缩放**：件数 = round(销量 / 100)，月需求 1,089 件 ≈ 产能 1,564 件/月的 69.6%；
- 产出 `data/teacher-orders-6parts-weekly.csv`：261 周 × 6 列；
- **诚实边界**：这是“零售销量映射”，不是真实机加工订单，报告要写清楚。

### 5.2 评价方法

- 按时间切：最后 8 周为测试集（2017-11-06 ~ 12-25），之前全部训练；
- MAPE = `100/n × Σ |(y-ŷ)/y|`，剔除 y=0；
- RMSE = `sqrt(mean((y-ŷ)²))`；
- **宏均**：每个零件先算 MAPE 再平均（同时给微均对照）；
- 线性缩放不改变 MAPE（分子分母同比例）。

### 5.3 四个模型与结果

| 模型 | 做法 | 平均 MAPE |
|---|---|---|
| 移动平均 MA(4) | 前 4 周均值，滚动一步 | 13.7%（静态外推 19.0%） |
| 季节朴素 | 去年同周 `ŷ_t = y_{t-52}` | 5.04% |
| 指数平滑 Holt-Winters | 趋势 + 52 周季节 | 介于两者之间 |
| **SARIMA(1,0,0)(0,1,0,52)+漂移** | AR(1) + 季节差分 + 漂移 | **3.66%** |

逐件 MAPE：2.49 / 3.99 / 2.99 / 3.09 / 4.40 / 4.98（%）。

### 5.4 老师可能问：SARIMA 参数为什么这么定？

1. 周粒度、52 周季节 → `seasonal_order` 周期固定 52；
2. `D=1` 季节差分去掉年度周期，`AR(1)` 抓周间相关，`trend='c'` 抓趋势；
3. 试过完整 `(1,1,1)(0,1,1,52)`：拟合 261 周要 **60 秒/产品**，答辩演示会卡死；实测 `(1,0,0)(0,1,0,52)+漂移` **0.6 秒/产品**、精度 3.66% 比基线 5.04% 好，所以第一代用这个；
4. 诚实：没做残差白噪声检验，是后续可补项。

### 5.5 代码位置

- `backend/apps/order/forecasting.py`：`load_series()`、`_holdout_predictions()`、`_fit()`、`run_forecast()`、`save_forecast()`；
- 接口：`POST /order/forecasts/run/`、`GET /order/forecasts/history/`、`GET /order/forecasts/`；
- 基线复现：`experiments/order_forecast_baseline.py`（4 种口径对照）。

## 6. 算法二：规则版排产（核心）

### 6.1 输入

- MPS 明细（产品 + 数量）；
- 每个产品的生效工艺路线（工序、标准工时、是否不占设备）；
- D 的设备能力表（哪些设备能做哪种工序、产能、状态）；
- 换型矩阵（前产品 → 后产品多少分钟）；
- 订单交期、优先级。

### 6.2 规则

1. 工单按 **(交期, 优先级)** 升序；
2. 工单内部按工序 **seq 串行**（上一道做完才做下一道）；
3. 每道工序选**最早可用**的合格设备（step_type 匹配、启用、状态 normal/wearing）；
4. 换产品时加换型时间（换型矩阵，缺 0）；
5. **不占设备**工序（下料/检验）只占工单时间；
6. 连续时间，起点对齐本地 08:00。

### 6.3 核心伪代码

```python
for 工单 in sorted(工单, key=(交期, 优先级)):
    prev_end = None
    for 工序 in 工单.路线.工序:
        duration = qty * 工序.std_hours * 60        # 分钟
        if 工序.is_equipment_free:
            start = prev_end or plan_start
        else:
            cap = min(合格设备, key=lambda c: equipment_available[c.equipment_id])
            eq = cap.equipment
            ready = equipment_available[eq.id]
            co = 换型矩阵.get(last_product[eq.id], 工单.product)   # 分钟
            start = max(ready + co, prev_end or plan_start)
            equipment_available[eq.id] = start + duration
            last_product[eq.id] = 工单.product
        end = start + duration
        prev_end = end
        # 写 pl_work_order_operation + pl_schedule_plan_detail
```

### 6.4 KPI

- `work_order_count` / `operation_count` / `changeover_count`；
- `makespan_hours = max(plan_end) - plan_start`；
- `on_time_rate = 计划完成 ≤ 交期的工单数 / 总工单数`；
- `equipment_load` = 设备占用分钟 / makespan；
- `warnings`（无可用设备等）。

### 6.5 为什么不用遗传算法/OR-Tools

1. 规模小（8 台设备、20 道工序），规则版毫秒级；
2. 可解释：能逐步讲清“为什么这台设备、这个时间”；
3. 课程重点是跑通闭环 + 可扩展；
4. 换算法只改 `planning/services.py`，接口/前端不动。

### 6.6 可能的追问（诚实答）

- 为什么不用 `capacity_per_hour`？标准工时是工艺定额，和 BOM/成本口径一致；产能用于选设备，第一代没做设备差异化工时，可改进。
- 171 小时太长？4 工单 20 工序串行，磨削/滚齿各 1 台，连续时间不扣休息。
- 为什么准时率 100%？计划 11-16 开始，交期 11-30 之后，余量够；压交期会掉。

## 7. 齐套 / 派工 / 转序 / 看板

### 7.1 齐套

```
需求 = Σ MPS数量 × 单件用量 × (1 + 损耗率/100)
可用 = C 的库存台账（批次流水正入负出求和）
缺口 = max(需求 - 可用, 0)
```

- `order/services.py → check_kit()`、`get_available_qty()`；
- 缺生效 BOM → 12019；MPS 无明细 → 12018；
- 当前库存流水为 0，`ready=false` 是真实结果；C 灌入库后自动变化。

### 7.2 派工

- 依据 A 的 `EmployeeSkill(user, step_type, level, is_certified)`；
- 自动派工：筛“有该工序技能且启用”，按 任务数少 → 等级高 排序；
- 派工后 `pending → dispatched`；无技能 **12025**；
- 演示：`WO202611-0002` 5 道工序 → 张/李/王。

### 7.3 转序搬运（B 与 D 的边界）

- B 输出工序间 leg：`work_order_code, operation_id, seq, from_workstation, to_workstation, from_node, to_node, qty, priority, plan_start`；
- D 的 `POST /logistics/transport-tasks/from-legs/` 批量建任务；
- 幂等键：优先 `operation_id`，其次 `(工单号, seq)`；
- 只对已下达工单派生；有已下达/生产中/已完工工单时 B 拒绝重排（12020）；
- 工单完工 → best-effort 调 D 的 `cancel-by-work-order`，撤 pending/assigned，running 不动。

边界一句话：**B 排“设备什么时候做哪道工序”，D 排“哪台 AGV 什么时候搬哪批料”；只通过“工序 → 搬运任务”一个口对接。**

### 7.4 看板

- `GET /planning/dashboard/` 聚合：方案 KPI、工单状态/工序完成数、C 的报工汇总、延迟工单、单台覆盖瓶颈、最近齐套状态；
- 报工/库存不可用时 try/except 降级为 0，看板不会打不开；
- 前端：工单进度堆叠柱；甘特图用 ECharts **custom series renderItem** 画时间条。
