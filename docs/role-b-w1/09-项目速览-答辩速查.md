## 一、30 秒版本（背下来）

> 我们做的是**面向中小型离散机加工车间的生产管理平台**（SmartWorks，类似一套简化版 MES + 7 个算法小模块）。
> 它把"销售订单 → 需求预测 → 主生产计划 → 齐套检查 → 排产 → 派工 → 领料 → AGV 搬运 → 加工报工 → 检验 → 成品入库 → 发货"这条链路串起来，再加上 7 项算法：AGV 单机/多机调度、路径规划、表面缺陷检测、物体识别、设备状态监测、订单需求预测。
> 四人分工：A 平台与集成（组长）、B 工艺与计划（我）、C 执行与质量、D 设备与物流调度。
> 进度：**第一周把项目骨架、接口契约、统一响应体、四人数据模型、教师数据集评估做完了，系统已经能登录、能跑通三种标准响应；现在（W3）开始写各业务模块，我这边是工艺配置（工序模板/产品族/工艺路线/BOM/换型矩阵）和订单排产。**

## 二、这个项目到底在解决什么（用车间的话讲）

一个机加工车间接单生产时，反复遇到 5 个问题，我们各用一个模块回答：

| 车间里的问题 | 我们的回答 | 对应模块 | 谁做 |
|---|---|---|---|
| 靠经验排产，急单一来全乱 | 需求预测 + 可视化排产 + 急单重排（冻结区不动已开工的） | M04 订单与预测、M05 排产 | **B** |
| 每换一个零件就要重新交代做法 | 工序模板库 + 产品族 + 工艺路线，新零件"只配参数不改代码" | M03 工艺配置 | **B** |
| 目检漏检、判据不一致 | 机器视觉质检 + SPC + 批次正逆向追溯 | M08 质量 | C |
| 设备坏了才修 | 传感器时序 + 状态识别 + 自动生成维修/换刀工单 | M10 设备 | D |
| 专人推车找料、路线随意 | AGV 台账 + 路网 + 搬运任务 + 单/多机调度 + 路径规划 | M11 物流 | D（路径 A） |

**演示级例子（讲给老师听最直观）**：
"车间接到一张法兰盘 A 的订单 → 系统按历史销量预测未来 4~8 周需求 → 生成主生产计划 → 用 BOM 和库存做齐套检查 → 按工艺路线（下料→粗车→精车→钻孔→检验）和设备能力排产、给出甘特图 → 班组长派工 → 仓管领料、AGV 搬运 → 操作工扫码报工 → 质检 → 成品入库 → 发货。换到端盖 B 时，系统按换型矩阵自动预留 15 分钟换型。"

## 十、缩写全解（老师问哪个就按"全称 → 中文 → 我们项目里指什么"回答）

### 10.1 制造与业务（MES/ERP 这一层）

| 缩写 | 英文全称 | 中文 | 在我们项目里指什么 |
|---|---|---|---|
| ERP | Enterprise Resource Planning | 企业资源计划 | 管理层系统，管订单/采购/库存/财务；我们只做其中订单与主数据一小块 |
| MES | Manufacturing Execution System | 制造执行系统 | 我们的主体：工单、派工、报工、工序流转、在制品、质量、追溯 |
| APS | Advanced Planning and Scheduling | 高级计划与排程 | 我们的排产模块（B 负责）：交期+产能+换型排序、甘特图、方案对比 |
| WMS | Warehouse Management System | 仓储管理系统 | 仓库、库位、批次、出入库、台账、盘点（C 管原料，D 管成品） |
| MRP | Material Requirements Planning | 物料需求计划 | 由 BOM 算"要买多少料"；我们只做到**齐套检查**，不做多层 MRP 展开（非目标） |
| MPS | Master Production Schedule | 主生产计划 | "什么时间生产多少"，由订单或需求预测生成，B 负责 |
| BOM | Bill of Materials | 物料清单 | 一个产品由哪些物料、用多少组成，齐套检查和领料靠它 |
| WIP | Work In Process | 在制品 | 已投产未完工的产品，卡在哪道工序、有多少（C 模块） |
| OEE | Overall Equipment Effectiveness | 设备综合效率 | 可用率 × 性能 × 良率，D 的设备看板指标 |
| SPC | Statistical Process Control | 统计过程控制 | 用控制图看过程是否稳定，C 的质量模块（X-bar / R 图） |
| CPK | Process Capability Index | 过程能力指数 | 衡量过程能不能稳定做出合格品（基础版，拓展） |
| IQC / IPQC / FQC | Incoming / In-Process / Final Quality Control | 来料 / 过程 / 成品检验 | 三种检验类型，C 的检验单 |
| AQL | Acceptable Quality Limit | 可接受质量限 | 抽样检验标准，我们检验单里写 AQL 1.0 |
| HMLV | High-Mix Low-Volume | 多品种小批量 | 我们产品的目标场景：4~6 种零件、小批量 |
| MTO | Make To Order | 按订单生产 | 我们的生产模式（接了单才排产） |
| AGV | Automated Guided Vehicle | 自动导引运输车 | 车间里的搬运小车，D 的调度对象 |
| PHM | Prognostics and Health Management | 故障预测与健康管理 | 设备健康管理，任务 6 的领域 |
| RUL | Remaining Useful Life | 剩余使用寿命 | 预测设备/刀具还能用多久（第一代不做，第二代） |
| KPI | Key Performance Indicator | 关键绩效指标 | 看板指标：达成率、良率、OEE、周转率等 |
| PDA | Personal Digital Assistant | 手持终端 | 操作工报工用的手持设备，我们重点做手机端页面 |

### 10.2 统计与算法

| 缩写 | 英文全称 | 中文 | 在我们项目里指什么 |
|---|---|---|---|
| **MAPE** | Mean Absolute Percentage Error | 平均绝对百分比误差 | 预测误差占真实值的百分比，越小越好；任务 7 的指标，我们基线 18.9% / 5.0% |
| RMSE | Root Mean Square Error | 均方根误差 | 误差平方的平均再开方，单位同销量；对大误差惩罚更重 |
| MAE | Mean Absolute Error | 平均绝对误差 | 误差绝对值的平均（补充指标） |
| sMAPE | symmetric MAPE | 对称平均绝对百分比误差 | 低销量时 MAPE 会爆炸，用它更稳（报告里说明用哪个） |
| MA | Moving Average | 移动平均 | 我们的弱基线：取最近 4 周均值往后预测 |
| Seasonal Naive | 同周去年法（季节朴素法） | — | 拿去年同一周的销量当预测；实测 MAPE 5.0%，**真正的强基线** |
| ARIMA | AutoRegressive Integrated Moving Average | 自回归积分滑动平均 | 时序预测经典模型：AR 用过去值、I 差分去趋势、MA 用过去误差 |
| SARIMA | Seasonal ARIMA | 季节性 ARIMA | ARIMA 加季节项（周期 52 周）；任务 7 主模型 |
| STL | Seasonal-Trend decomposition using LOESS | 季节-趋势分解 | 把序列拆成趋势/季节/残差（W5 备选） |
| ETS | Error-Trend-Seasonal | 指数平滑模型族 | 另一类时序基线/备选 |
| CV | Coefficient of Variation | 变异系数 | 标准差 ÷ 均值，衡量波动；我们算过 6 零件周销量 CV≈0.21 |
| SVM | Support Vector Machine | 支持向量机 | 任务 6 设备状态分类的备选模型 |
| RF | Random Forest | 随机森林 | 任务 6 的另一个备选（可解释性较好） |
| YOLO | You Only Look Once | 一种目标检测模型 | 图片标注格式以其命名；我们的图像标签就是 YOLO 格式 |
| IoU | Intersection over Union | 交并比 | 检测框/分割区域与真值的重合度，任务 4/5 可报指标 |
| NEU-DET | Northeast University Surface Defect Database | 东北大学表面缺陷数据集 | 教师给的图像数据就是它（6 类 × 300 张） |
| CWRU | Case Western Reserve University Bearing Data | 凯斯西储轴承数据集 | 任务 6 公开数据集备选 |
| MVTec AD | MVTec Anomaly Detection | 工业异常检测数据集 | 任务 4/5 泛化验证备选 |
| TSP | Travelling Salesman Problem | 旅行商问题 | 单台 AGV 跑多个任务的最优顺序 = TSP 变体（任务 1） |
| 2-opt | two-opt local search | 两交换局部搜索 | 任务 1 在最近邻基础上改进的方法 |
| CP-SAT | Constraint Programming – Satisfiability | 约束规划求解器 | OR-Tools 里的求解器，任务 2 多机调度备选 |
| Dijkstra | Dijkstra's algorithm | 迪杰斯特拉算法 | 任务 3 加权最短路 |
| A* | A-star algorithm | A 星算法 | 任务 3 带启发式的最短路（比 Dijkstra 快） |
| BFS | Breadth-First Search | 广度优先搜索 | 任务 3 的对比基线 |

### 10.3 开发与接口

| 缩写 | 英文全称 | 中文 | 在我们项目里指什么 |
|---|---|---|---|
| API | Application Programming Interface | 应用编程接口 | 前后端之间的接口，如 `/api/v1/process/templates/` |
| REST | Representational State Transfer | 表述性状态转移 | 一种接口风格（GET/POST/PUT/DELETE 资源） |
| DRF | Django REST Framework | Django 的 REST 接口框架 | 我们后端的接口框架 |
| CRUD | Create / Read / Update / Delete | 增删改查 | 每个业务模块最基本的功能 |
| ORM | Object-Relational Mapping | 对象关系映射 | Django 用模型类操作数据库，不手写 SQL |
| JSON | JavaScript Object Notation | 一种数据格式 | 接口请求/响应都用它；统一响应体 `{code,message,data}` |
| JSONB | JSON Binary | PostgreSQL 的二进制 JSON 类型 | 存动态参数（工艺参数、设备参数、KPI） |
| SQL | Structured Query Language | 结构化查询语言 | 数据库查询语言（我们主要用 ORM） |
| PK / FK | Primary Key / Foreign Key | 主键 / 外键 | 主键统一 `id`；外键统一 `xxx_id` |
| CORS | Cross-Origin Resource Sharing | 跨域资源共享 | 前端 5173 访问后端 8000 需要它 |
| PAT | Personal Access Token | 个人访问令牌 | GitHub 推送用的 `ghp_...` 令牌，不是密码 |
| Swagger | Swagger / OpenAPI | 接口文档工具 | 用 drf-spectacular 自动生成，地址 `/api/docs/` |
| UAT | User Acceptance Test | 用户验收测试 | 不专门做，用课程验收标准代替 |
