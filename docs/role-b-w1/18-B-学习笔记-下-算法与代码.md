## 2. 回归建模（对应课件第三章）——理解“拟合”和“过拟合”

### 2.1 回归是什么

给定输入 x 和输出 y，找一个函数 f，使 `y ≈ f(x)`。

课件里的质量预测例子：

```
质量 q = f(材料特性 C, 工艺参数 x) + 噪声
```

我们预测订单的例子：

```
未来需求 = f(历史需求) + 噪声
```

### 2.2 最小二乘

假设用直线 `y = w0 + w1*x` 拟合数据，误差平方和：

```
E(w) = Σ (y_i - (w0 + w1*x_i))²
```

让 E 最小，就得到“最贴合数据”的 w0、w1。这就是**最小二乘法**（课件第三章）。

### 2.3 过拟合与正则化（考试/答辩常考概念）

- **欠拟合**：模型太简单，连训练数据都拟合不好；
- **过拟合**：模型太复杂，把噪声也背下来了，训练集很好、新数据很差；
- 课件例子：9 阶多项式能穿过所有点，但剧烈震荡；
- 解决：
  1. 增加数据；
  2. 降低模型复杂度；
  3. **正则化**（岭回归 L2、Lasso L1）：在误差里加“惩罚项”，限制参数太大。

### 2.4 训练集 / 验证集 / 测试集

- 训练集：用来学参数；
- 验证集：用来选模型/调参；
- 测试集：最后只用一次，评估真实效果。

**我们的预测**：前 253 周训练、最后 8 周测试。这是在模拟“用过去预测未来”，不能随机打乱（时间序列有时间顺序）。

### 2.5 回归 vs 时间序列

| | 回归 | 时间序列 |
|---|---|---|
| 输入 | 多个特征 x（温度、压力…） | 历史值本身（t-1、t-52…） |
| 例子 | 质量预测 | 订单预测 |
| 关键假设 | 样本独立 | 相邻时间相关 |

我们的任务 7 是**单变量时间序列**：只用历史需求预测未来需求。

## 3. 时间序列预测（任务 7，重点）

### 3.1 什么是时间序列

按时间顺序排列的一串数：

```
第1周 31，第2周 29，第3周 26，……，第261周 51
```

时间序列通常由三部分组成：

- **趋势（Trend）**：长期上升/下降；
- **季节（Seasonality）**：固定周期重复（52 周/年）；
- **噪声（Noise）**：随机波动，无法预测。

### 3.2 四个模型（从简单到复杂）

#### ① 移动平均 MA(k)

用最近 k 周的平均值预测：

```
ŷ_t = (y_{t-1} + y_{t-2} + ... + y_{t-k}) / k
```

例：最近 4 周 10、12、14、16 → 预测下周 = 13。

优点：平滑噪声；缺点：滞后，跟不上趋势/季节。

#### ② 季节朴素（seasonal naive）

用去年同周：

```
ŷ_t = y_{t-52}
```

优点：稳定季节数据很强；缺点：没趋势时好用，有趋势会滞后一年。

#### ③ 指数平滑（Holt-Winters）

给最近数据更大权重，同时建模趋势和季节：

```
ŷ_{t+1} = α·y_t + (1-α)·ŷ_t     （简单指数平滑的直觉）
```

Holt-Winters 在此基础加上趋势项和季节项。

#### ④ SARIMA

名字拆开：

- **AR（自回归）**：用过去的**值**预测现在；
- **MA（移动平均）**：用过去的**预测误差**修正；
- **I（差分）**：做差去掉趋势；
- **S（季节）**：在周期 52 上做同样操作。

记号 `(p,d,q)(P,D,Q,s)`：

| 符号 | 含义 | 我们的值 |
|---|---|---|
| p | 普通 AR 阶数 | 1 |
| d | 普通差分次数 | 0 |
| q | 普通 MA 阶数 | 0 |
| P | 季节 AR 阶数 | 0 |
| D | 季节差分次数 | 1 |
| Q | 季节 MA 阶数 | 0 |
| s | 季节周期 | 52 |

**算式直觉**：

```
季节差分：z_t = y_t - y_{t-52}      # 去掉“今年比去年高/低”的年度模式
AR(1)：   z_t = c + φ·z_{t-1} + ε_t # 用上一周差分预测本周差分
漂移 c：   允许长期趋势
```

### 3.3 为什么用这个配置（工程取舍）

完整配置 `(1,1,1)(0,1,1,52)` 拟合 261 周要 **60 秒/产品**，6 个产品 6 分钟，答辩/演示会卡死。实测：

| 配置 | 单产品耗时 | 平均 MAPE |
|---|---|---|
| (1,0,0)(0,1,0,52)+漂移 | **0.6 秒** | **3.66%** |
| (1,1,1)(0,1,1,52) | 60 秒 | 没跑完（太慢） |

所以选择“季节差分 + AR(1) + 漂移”，在精度和速度之间取平衡。**这不是作弊，是工程决策。**

### 3.4 怎么评价预测好坏：MAPE、RMSE

**MAPE**（平均绝对百分比误差）：

```
MAPE = 100% / n × Σ |y_i - ŷ_i| / y_i
```

例子：

| 真实 y | 预测 ŷ | 绝对百分比误差 |
|---|---|---|
| 100 | 90 | 10% |
| 50 | 55 | 10% |
| 12 | 13 | 8.3% |

平均 = (10+10+8.3)/3 = 9.4%。

**RMSE**：

```
RMSE = sqrt( (1/n) × Σ (y_i - ŷ_i)² )
```

对大误差更敏感。

**为什么要剔除 y=0**：除以 0 会无穷大；而且需求为 0 的周没有百分比意义。

**宏均 vs 微均**：

- 宏均：每个零件先算 MAPE，再平均（每个零件权重相同）；
- 微均：所有误差求和 / 所有真实值求和（大销量零件权重大）。

我们用宏均，避免小零件被大零件“平均掉”。

## 4. 优化与排产（对应课件第四章 + 我们的规则版）

### 4.1 优化问题的三要素（课件第四章）

```
目标函数：要最小化/最大化的东西（如 makespan）
决策变量：可以决定的量（每道工序在哪台设备、几点开始）
约束条件：不能违反的规则（工序顺序、设备不能同时做两件、换型时间）
```

我们的排产：

- 目标：尽量按时交货、缩短 makespan；
- 决策变量：每道工序的设备 + 开始时间；
- 约束：路线顺序、设备唯一、换型、不占设备工序。

### 4.2 求解方法分类（课件第四章 1.2）

| 类别 | 例子 | 特点 |
|---|---|---|
| 精确求解 | 线性规划、整数规划、动态规划 | 能保证最优，但要求模型形式严格、规模大时慢 |
| 启发式 | 遗传算法 GA、粒子群 PSO、禁忌搜索 | 近似解，适合复杂约束/大规模 |
| 强化学习 | Q-learning、DQN | 通过试错学策略 |

课件第八周还给了 **GA 求解调度**、**PSO 求解 AGV 任务顺序** 的代码示例。

### 4.3 遗传算法 GA 的直觉（课件第四章）

1. 种群：很多个“调度方案”；
2. 适应度：每个方案算 makespan（越小越好）；
3. 选择：好的方案更容易被选中繁殖（轮盘赌）；
4. 交叉：两个方案交换部分工序顺序，产生新方案；
5. 变异：随机交换某两道工序，增加多样性；
6. 迭代若干代，得到近似最优解。

一句话：**模拟“优胜劣汰 + 交配 + 变异”来搜索方案。**

### 4.4 粒子群 PSO 的直觉

每个“粒子”是一个方案，粒子有位置/速度，向“自己历史最好”和“群体历史最好”靠拢。适合连续变量优化；调度问题要先把方案编码成向量。

### 4.5 我们的排产为什么用规则（贪心）而不是 GA/PSO

| 原因 | 说明 |
|---|---|
| 规模小 | 8 台设备、20 道工序，贪心毫秒出结果 |
| 可解释 | 能解释“为什么选这台设备/这个时间”，答辩/生产现场需要 |
| 分工 | 课程里 GA/PSO 主要给 AGV 调度（任务 1~3，D 负责）；B 的排产是工程化计划 |
| 可扩展 | 真要换算法，只改 `planning/services.py`，接口/前端不变 |

### 4.6 规则版排产步骤

1. 工单按 **交期早 → 优先级高** 排序；
2. 工单内部按工序顺序串行；
3. 每道工序选“能干这道工序、且最早空出来”的设备；
4. 设备上次做的产品不同 → 加换型时间；
5. 下料/检验不占设备，直接接在上一道后面；
6. 记录每道工序的开始/结束，算 KPI。

`backend/apps/planning/services.py`：

```python
for item, due, order in work_orders:
    wo = WorkOrder.objects.create(...)      # 建工单
    prev_end = None                         # 上一道工序结束时间
    for step in route_steps(item.product):  # 按路线逐道工序
        # 单件工时 × 数量 = 总分钟数；至少 1 分钟
        duration = max(int(item.qty * step.std_hours * 60), 1)

        if step.is_equipment_free:
            # 下料/检验：不占设备，从上一道结束开始
            start = prev_end or start_at
        else:
            # 找能做这道工序的设备（只按 step_type 匹配）
            pool = _equipment_pool(step.step_type)
            # 选最早空出来的那台
            best = min(pool, key=lambda c: equipment_available.get(c.equipment_id, start_at))
            eq = best.equipment

            # 换型：如果这台设备上次做的是别的产品，要加换型分钟
            co = _changeover_minutes(last_product.get(eq.id), item.product)

            # 开始时间 = max(设备可用时间 + 换型, 上一道工序结束)
            start = max(equipment_available.get(eq.id, start_at)
                        + timedelta(minutes=co),
                        prev_end or start_at)

            # 更新设备可用时间、设备上次做的产品
            equipment_available[eq.id] = start + timedelta(minutes=duration)
            last_product[eq.id] = item.product

        end = start + timedelta(minutes=duration)   # 这道工序结束
        prev_end = end                              # 给下一道用
        # 保存 WorkOrderOperation 和 SchedulePlanDetail（甘特数据）
```

### 4.8 KPI 怎么算

```
makespan      = 最晚结束 - 计划开始
on_time_rate  = 计划完成 ≤ 交期的工单数 / 总工单数
equipment_load= 设备被占分钟 / makespan
换型次数      = 设备切换产品的次数
```

### 4.9 局限（学习时要知道）

1. 连续时间，不扣午休/夜班；
2. 工单内部串行，不能并行；
3. 用标准工时，不按设备产能差异化；
4. 没考虑设备故障/急单插单；
5. 贪心不保证全局最优。

这些不是“错误”，是**第一代的合理简化**；报告里要写清楚。

## 5. 齐套、敏感性分析、派工

### 5.1 齐套（BOM 展开）

```
1. 对 MPS 每个产品找生效 BOM；
2. 对 BOM 每行物料：
   需求 += 计划数量 × 单件用量 × (1 + 损耗率/100)
3. 查库存可用量（C 的库存台账：入库正、领料负，求和）；
4. 缺口 = max(需求 - 可用, 0)；
5. 全部缺口 = 0 → 齐套。
```

代码（简化，带注释）：

```python
required = {}  # 物料 → 总需求
for item in mps.items.select_related('product'):
    # 一个产品可能有多个 BOM 版本，只取 active
    bom = Bom.objects.filter(product=item.product, status='active').first()
    if not bom:
        raise BizError(12019, '缺少生效 BOM')

    for bi in bom.items.select_related('material'):
        # 含损耗：1 + 5% = 1.05

               (1 + Decimal(bi.loss_rate) / 100)
        required[bi.material] = required.get(bi.material, Decimal('0')) + need

# 批量查库存可用量（C 的 I-09）
available_map = get_available_qty_map(list(required.keys()))
for material, need in required.items():
    available = available_map.get(material.id, Decimal('0'))
    shortage = max(need - available, Decimal('0'))
    # 写 or_material_requirement
```

### 5.2 换型敏感性分析

问题：D 给的换型时间是估算的，估错 ±50% 会不会改变结论？

做法：

1. 把换型矩阵所有值乘 0.5 / 1.0 / 1.5；
2. 各排一次产；
3. 比较 makespan、准时率。

结果：

| 换型系数 | makespan(h) | 相对变化 |
|---|---|---|
| 0.5x | 170.5 | −0.3% |
| 1.0x | 171.0 | 0 |
| 1.5x | 171.5 | +0.3% |

结论：换型不是瓶颈；磨削（2.5 件/h）和滚齿（1.8 件/h）才是。

### 5.3 派工

约束：每个人只有部分工序技能（A 的 `EmployeeSkill`）。

规则：

1. 筛“有该工序技能且启用”的人；
2. 优先派给当前任务少的人（负载均衡）；
3. 任务数相同看等级（高级优先）。

```python
@transaction.atomic  # 整个函数是一个事务
def create_order(validated_data):
    data = dict(validated_data)
    items = data.pop('items', [])       # 明细单独拿出来
    validate_order_payload(data)        # 校验交期（失败抛 BizError）
    order = SalesOrder.objects.create(**data)  # ① 建订单
    for item in items:
        OrderItem.objects.create(order=order, **item)  # ② 建明细
    return order
    # 如果 ② 中途失败，① 也会回滚，不会出现“有订单没明细”的脏数据
```

```js
      },
      style: api.style(),  // 颜色

  },
  data,  // 每项：[行号, 开始时间戳, 结束时间戳]
```
