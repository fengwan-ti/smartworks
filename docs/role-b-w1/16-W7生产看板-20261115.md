# W7 生产看板（B 侧，2026-11-15）

> 负责人：B ｜ 页面：`/planning/dashboard` ｜ 接口：`GET /api/v1/planning/dashboard/`

## 1. 数据来源（全部是真实接口/表，不是静态图）

| 区块 | 来源 |
|---|---|
| 最新排产方案 / makespan / 准时率 / 设备负荷 | `pl_schedule_plan.kpi` + `pl_schedule_plan_detail` |
| 工单状态 / 工序完成数 / 延迟 | `pl_work_order` + `pl_work_order_operation` |
| 报工良品/不良 | C 的 `production.services.wip_summary()`（I-08） |
| 后续可加：齐套/库存 | C 的 I-09（已有接口） |

## 2. 页面内容

- KPI 卡片：工单总数、延迟工单、工序完成数（done/total）、报工良品/不良、方案总跨度、方案准时率；
- ECharts 堆叠柱：每个工单「已完成工序 / 未完成工序」；
- 最新方案设备负荷表 + 工单状态分布；
- 工单明细表：产品、数量、交期、状态、工序进度、报工良品/不良、延迟标记。

## 3. 实测（当前演示库）

```
plan=SP20261115-001  wos=4  delayed=0  ops=1/20  reportedGood=0
WO202611-0001 已完工 0/5（历史手工完工，工序状态已回填）
WO202611-0002 生产中 1/5（C 的报工开工了 1 道）
WO202611-0003 已排产 0/6
WO202611-0004 已排产 0/4
```

`reportedGood=0` 是真实结果：C 的报工表里还没有数量；C 录几条报工后刷新看板就会变化。

## 4. 说明

- 看板只读，不写任何业务状态；
- C 的 `wip_summary` 不可用时自动降级为 0（不影响看板打开）；
- 菜单已本地插入（`planning_dashboard`），需要 A 收编进 `init_core`。

## 5. 演示脚本

1. 订单 → 确认；
2. 主生产计划 → 从订单生成；
3. 齐套检查（有库存则显示缺口变化）；
4. 排产与甘特图 → 运行排产 → 自动派工 → 派生搬运任务；
5. 生产看板 → 展示工单进度；C 报工后刷新，工序完成数/良品数变化。
